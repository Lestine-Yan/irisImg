# irisImg v0.1.1 发布说明

> **版本**：v0.1.1
> **发布日期**：2026-10-11
> **产物**：`irisImg-0.1.1-linux-amd64.tar.gz`

v0.1.1 是初版之后的第一个迭代版本。主线是**音频中心全链路**——irisImg 从个人图床扩展为「图片 + 音频」双媒体服务：后端新增 mp3/m4a/flac 的魔数嗅探、元数据解析、内嵌封面抽取与全套管理接口，前端新增音频中心（上传 / 列表 / 全局播放 / 改封面 / 批量删除），Nginx 与配置模板同步对齐。同时补齐内容管理体验（图片批量删除、日志分级清理、通用分页组件），并将发布链路自动化（推 tag 即自动测试 + 构建 + 发 Release）。

---

## 一、新特性

### 1. 音频中心（#21，本版主线）

**后端**（详见 [docs/backend/AUDIO.md](../backend/AUDIO.md)）：

- **格式与安全**：支持 mp3 / m4a / flac，内容魔数嗅探 + 白名单（不信任客户端 `Content-Type`）；m4a 走 MP4 结构校验（`moov.trak.mdia.hdlr` 有 `soun` 无 `vide` 才放行），被改名的视频 mp4 直接拒收。
- **元数据解析永不失败**：标题 / 艺术家 / 专辑等标签、精确时长（mp3 帧遍历，VBR 也准）、FLAC STREAMINFO（采样率 / 声道 / 位深）、m4a `mvhd`；子解析失败零值降级，绝不阻断上传。
- **内嵌封面内容寻址共享**：best-effort 抽取到 `covers/<sha256>.<ext>`，多首共用同一封面的音频只落一份文件；`PATCH /admin/audios/:id` 可覆盖封面 URL，传空串恢复内嵌默认。
- **与图片同款存储语义**：SHA256 秒传、原子写盘、`path.Clean` 拒绝绝对路径与 `..` 逃逸；`audio_root_dir` 误配启动期 fail-fast。
- **删除密钥级联清理音频**（响应新增 `audios_removed` 计数）；审计事件 `audio.upload` / `audio.delete` / `audio.update_cover`。
- **双通道**：对外 `POST /api/v1/audios`（API Key `readwrite` + 按密钥限流，对称图片接口）；后台 `/admin/audios` 全套（JWT + HTTPSOnly）。
- **静态服务**：`/audios` 挂音频 + 封面图片扩展名白名单，与 `/imgs` 同款旁路防御。

**前端**：

- 侧边栏拆分「图片」「音频」两个中心；音频列表为纵向堆叠条卡（封面 / 播放按钮 / 标题 / 艺术家—专辑 / 时长·格式·大小·日期）。
- **全局单例播放器**：`useAudioPlayer` 模块级 `HTMLAudioElement` + `useState` 共享，全局同时至多一个在播，切列表不打断也不叠音。
- 上传面板（`accept` 限定三格式 + 拖入过滤）、详情弹窗（Teleport 双栏全量元数据 + 封面覆盖编辑）、批量删除（账号密码二次确认）。

**部署对齐**：

- Nginx 模板新增 `location /audios/`（`alias data/audios/`，扩展名白名单 `mp3|m4a|flac|png|jpe?g|gif|webp`，`expires 30d immutable`）；`client_max_body_size` 25m → **150m**，`/api/` `proxy_read_timeout` 60s → **300s**（100MB 音频慢速上行会超 60s）。
- 新配置键：`storage.audio_root_dir`（默认 `data/audios`）/ `audio_public_base_url` / `audio_max_upload_size_mb`（默认 100）/ `audio_allowed_mime_types`（mpeg+mp4+x-m4a+flac）。

### 2. 图片多选批量删除（#19）

- 后端 `DELETE /admin/images` 批量接口：`ids` 非空、每项 >0、上限 100；账号密码二次确认失败返 **403**（不触发前端全局登出）；先取现存记录再逐张 best-effort 删物理文件、批量删记录，幂等可重试。
- 前端内容中心多选模式：跨页保留选中、切换 Key 筛选自动退出多选、删除后本地计算页码收敛再刷新；`ImageCard` 选中态描边 + 勾徽标。
- `/admin/images` 整组移入 **HTTPSOnly** 分组（见升级注意）。

### 3. 日志分级清理（#18）

- 原「清理日志」改为「清理全部日志」，旁增「清理GET日志」（`scope=get` 仅清 info 级 GET 请求日志，业务审计事件 `method` 为 NULL 不会被命中）。
- 清理后补记 `log.clear_get` 审计事件，与 `log.clear` 同款「清过留痕」语义；请求体向后兼容（不传 `scope` = 清全部）。

### 4. 通用分页组件（#20）

- 新建 `<UiPagination>`：页码按钮 + 省略号折叠（`1 … 4 5 6 7 8 9 10 … 16`）、首末页固定可见可点即直达、loading 整体禁用。
- 日志中心与内容中心接入，替换各自复制的「上一页/计数/下一页」按钮组；后端零改动。

### 5. 发布链路自动化（CI）

- 新增 [`.github/workflows/release.yml`](../../.github/workflows/release.yml)：推送 `v*` tag 自动触发「`go vet` + `go test` 门禁 → 复用 `build-release.sh` 构建 → 以 release commit 的 body 为发布说明 → 上传 tar.gz 并发布 GitHub Release」。
- 说明缺失或产物缺失均判失败；从本版本起 Release 在 GitHub 上自动产出。

## 二、接口变化（均为新增）

```
/api/v1
├── ── (JWTAuth + HTTPSOnly)
│   ├── GET    /admin/audios        分页 + 过滤（对称 /admin/images）
│   ├── POST   /admin/audios        后台直传上传（key_id=nil）
│   ├── DELETE /admin/audios        批量删除（密码二次确认）
│   ├── PATCH  /admin/audios/:id    改封面（空串=恢复内嵌默认）
│   └── DELETE /admin/images        图片批量删除（密码二次确认，上限 100）★
│       （GET/POST /admin/images 移入 HTTPSOnly 分组）
└── ── (APIKeyAuth)
    ├── POST /audios                添加音频（需 readwrite + 限流）
    └── GET  /audios                占位，返回 501（对称 /images）
```

新增审计事件：`audio.upload` / `audio.delete`（warn）/ `audio.update_cover` / `log.clear_get`。

## 三、升级注意（v0.1.0 → v0.1.1）

1. **配置不会炸启动**：旧 `config.yaml` 缺 `audio_*` 四键时 `ApplyDefaults` 自动补默认值（`data/audios` / 100MB / mp3+m4a+flac），升级即用；仍建议 `diff config/config.yaml config.yaml.example` 合并新键。
2. **Nginx 必须手动加 `/audios/` location**（拷贝新 `.example` 模板或对照补充），否则音频直链 404；同时把 `client_max_body_size` 提到大于 100m、`/api/` 超时放宽到 300s。
3. **`/admin/images` 现要求 HTTPS**（从 JWT 组移入 HTTPSOnly 组，与其他 `/admin/*` 语义对齐）：`apikey.https_only: true` 的生产部署若经 HTTP 访问后台图片接口，将返回 403。
4. **数据库自动迁移**：新增 `audios` 表（纯新增），`auto_migrate` 建表不破坏旧数据；`audios.api_keys` 外键 `ON DELETE SET NULL`。

## 五、已知限制（本版增量）

- 对外 `GET /api/v1/audios` 与 `GET /api/v1/images` 一样为 501 占位，对外列表语义待定。
- 封面仅支持「内嵌抽取 + 覆盖 URL」两种来源，无独立封面图片上传。
- 删除音频不删 `covers/` 共享封面（多音频可能共用一份，引用计数未做）。
- 播放器为全局单例：无播放列表、无顺序播放、进度不持久化；拖动进度依赖 Nginx 原生 Range 支持。
- mp4 家族容器按音轨结构校验放行（brand 不可靠），即「m4a 之外的 mp4 一律视作视频拒收」。
